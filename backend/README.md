# Backend del asistente CECAPI (Módulo 3)

Servidor FastAPI al que la app le manda las preguntas de IA; las claves viven solo aquí, nunca en el APK.
1. Instala: `pip install -r requirements.txt` (con el entorno virtual activado).
2. Copia `.env.example` como `.env` y pon `GEMINI_API_KEY` y `GROQ_API_KEY`; `.env` no se sube al repo.
3. Arranca: `uvicorn main:app --host 0.0.0.0 --port 8000`.
4. En la app, pon en `local.properties` (raíz del repo, no se sube) `cecapi.servidor=http://<IP-de-tu-PC>:8000` y, si el servidor tiene `CECAPI_CLAVE_APP`, `cecapi.claveApp=<esa clave>`. La app la manda en `X-Clave-App`.
Endpoints: `POST /preguntar` `{"pregunta","contexto"}` → `{"respuesta","proveedor","hayMas"}` · `POST /entender` (mismo cuerpo) → `{"tipo":"comando","comando"}` o `{"tipo":"respuesta",...}` · `POST /ver` `{"imagen" (base64),"modo":"billete"|"escena"}` → `{"respuesta","proveedor"}` · `POST /documento` `{"pedido"}` → `{"documento","aviso","proveedor"}` (pantalla Consultas; texto largo, datos que faltan entre corchetes) · `GET /uso` · `GET /estadisticas?dias=7` · `GET /panel` (página para ver el uso en el navegador; pide la clave) · `GET /`.
Respaldo: el orden sale de `IA_ORDEN` en `.env` (por defecto `groq,gemini`); si el primero falla, tarda más de `IA_TIEMPO_LIMITE_S` o agota su límite, contesta el siguiente.
Visión (`/ver`): `imagenes.py` endereza, reduce y quita el EXIF de la foto; `proveedores.ver_con_respaldo()` sigue el mismo `IA_ORDEN`. Gemini usa su mismo `GEMINI_MODEL` y Groq usa `GROQ_VISION_MODEL` (`qwen/qwen3.8-27b`), porque `GROQ_MODEL` es solo texto. La respuesta se limita a `VISION_MAX_TOKENS`.
Límites diarios en `.env` (`*_LIMITE_DIARIO`): avisa en el log al 80% y al 100% salta al respaldo. En Groq se acaban antes los tokens que las peticiones (ver `.env.example`).
Base de datos (`db.py`): sin `DATABASE_URL` usa `backend/cecapi.db` (SQLite, se crea sola); publicada usa PostgreSQL en Neon. Guarda el uso diario (`uso_diario`) y una fila por petición (`peticiones`: ruta, resultado, IA y milisegundos, **sin** texto, foto ni IP). Tablas con Alembic: `alembic upgrade head` ([migraciones/README.md](migraciones/README.md)).
Publicar en Render + Neon: [PUBLICAR.md](PUBLICAR.md).
Voz (`proveedores.py`): si una respuesta trae palabras de vista (revisa, verifica, pantalla, ves...) se pide a la misma IA una vez que la repita sin ellas. `GROQ_TEMPERATURA` (0.3) baja los datos inventados.
Seguridad (`seguridad.py`): si `CECAPI_CLAVE_APP` tiene valor, `/preguntar`, `/entender`, `/ver` y `/uso` piden el encabezado `X-Clave-App` con esa clave (401 si falta). Cada IP puede hacer `LIMITE_POR_MINUTO` peticiones por minuto (429 si se pasa). `contexto` acepta hasta 20 líneas de 1,000 caracteres; la IA recibe las últimas 6, sin las que traigan datos sensibles.
Privacidad (`privacidad.py`): bloquea la pregunta si trae correo, teléfono (aunque tenga espacios), tarjeta, CURP, RFC o el valor de una contraseña o PIN; preguntar por ellos sí pasa.
Código: `main.py` (rutas; es el único servidor), `comandos.py` (frases que abren un módulo), `privacidad.py` (bloquea contraseñas y datos personales), `proveedores.py` (Gemini, Groq y respaldo), `imagenes.py` (prepara las fotos), `seguridad.py` (clave de la app y límite por minuto), `prompts_vision.py` (prompts de billete y escena), `uso.py` (contador diario), `db.py` (tablas y conexión), `panel.html` (página de /panel), `migraciones/` (Alembic).
Pruebas automáticas (no llaman a la IA ni gastan cuota): `pip install -r requirements-pruebas.txt` y luego, dentro de `backend/`, `python -m pytest -v`. Pruebas con la IA real: `python docs/Pruebas/correr_pruebas.py` corre las 30 preguntas y los 20 sinónimos y escribe `docs/Pruebas/resultados.md`; `python test_imagenes.py` (dentro de `backend/`) prueba `imagenes.py`. Tablas propuestas para guardar todo esto: [docs/referencia/tablas-servidor.md](../docs/referencia/tablas-servidor.md).
